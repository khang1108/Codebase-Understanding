> Do **not** flatten the whole codebase into one anonymous document.
>
> Flatten it into a **structured document** where every chunk keeps metadata: `file_path`, `language`, `start_line`, `end_line`, `function/class name if possible`.

That gives us simple RAG now, while still allowing graph/static-analysis later.

---

# MVP Goal

Build a simple local codebase RAG system:

```plaintext
flowchart TD
    A[Source Code Repo] --> B[File Scanner]
    B --> C[Code Flattener]
    C --> D[Chunker]
    D --> E[Embedding Model]
    E --> F[Vector DB: Qdrant / FAISS]
    U[User NL Query] --> G[Retriever]
    F --> G
    G --> H[LLM Answer Generator]
    H --> I[Answer with Source Files + Lines]
```

MVP features:

```plaintext
1. Upload or point to a codebase folder.
2. Index source code files.
3. Ask natural-language questions.
4. Retrieve relevant chunks.
5. Generate answer with citations: file path + line range.
6. Show retrieved chunks for debugging.
```

# Team split: 3 members

## Member 1 — Codebase ingestion + chunking

**Main responsibility:** turn source code into clean retrievable chunks.

### Tasks

```plaintext
1. Build repo/file scanner.
2. Ignore useless folders:
   - .git
   - node_modules
   - venv
   - dist
   - build
   - __pycache__
   - .next
   - coverage
3. Support common source extensions:
   - .py, .js, .ts, .tsx, .java, .go, .cpp, .h, .cs
   - .md, .json, .yaml, .yml for docs/config
4. Flatten code into structured documents.
5. Add metadata:
   - file_path
   - language
   - start_line
   - end_line
   - chunk_id
   - repo_name
6. Implement chunking.
```

### Recommended chunk format

```plaintext
{
  "chunk_id": "src/payment/service.py:40-90",
  "file_path": "src/payment/service.py",
  "language": "python",
  "start_line": 40,
  "end_line": 90,
  "text": "class PaymentService:\n    def charge(...): ..."
}
```

### MVP chunking strategy

Use simple line-based chunking first:

```plaintext
chunk_size: 80–120 lines
overlap: 15–25 lines
```

This is simple and reliable enough for MVP.

Later, we can upgrade to function-level chunking with Tree-sitter.

### Deliverables

```plaintext
- scan_repo(path) -> list[FileDocument]
- chunk_file(file) -> list[CodeChunk]
- metadata preserved correctly
- ignored folders handled
- test on one small repo
```

### Definition of done

```plaintext
Given a repo path, Member 1 can produce chunks with correct file path and line numbers.
```

## Member 2 — Embedding + vector database + retriever

**Main responsibility:** store chunks and retrieve relevant code chunks from natural-language queries.

### Tasks

```plaintext
1. Choose vector DB:
   - Qdrant recommended
   - FAISS acceptable for quick prototype
2. Choose embedding model:
   - local: bge-small-en-v1.5, nomic-embed-text, all-MiniLM
   - API-based: OpenAI text-embedding-3-small
3. Create collection/index.
4. Insert chunks with metadata.
5. Implement search:
   - input: natural-language query
   - output: top-k relevant chunks
6. Add filtering:
   - by language
   - by file path
   - by repo name
7. Return score + metadata.
```

### Recommended MVP choice

Use **Qdrant** if we want a local knowledge base:

```plaintext
Vector DB: Qdrant local via Docker
Embedding: sentence-transformers/all-MiniLM-L6-v2 or bge-small-en-v1.5
Top-k: 8 to 12 chunks
```

### Retrieval function

```plaintext
retrieve(
    query: str,
    top_k: int = 8,
    filters: dict | None = None
) -> list[RetrievedChunk]
```

Each result should include:

```plaintext
{
  "score": 0.82,
  "file_path": "src/auth/login.py",
  "start_line": 20,
  "end_line": 75,
  "text": "..."
}
```

### Deliverables

```plaintext
- create_vector_collection()
- embed_chunks(chunks)
- upsert_chunks(chunks)
- retrieve(query, top_k)
- simple retrieval test script
```

### Definition of done

```plaintext
Given the query “where is login handled?”, the retriever returns chunks from auth/login-related files.
```


For fastest MVP, use:

# Important MVP warning

Flattening all code into one document is okay only if you preserve headers like this:

```plaintext
===== FILE: src/auth/login.py =====
===== LANGUAGE: python =====
===== LINES: 1-120 =====

<code here>
```

But for retrieval, it is better to chunk per file:

```plaintext
file → chunks
```

Do **not** do this:

```plaintext
whole repo → one giant text → random chunks
```

Because then the system may lose file boundaries and give weak citations.

# Final MVP target

By the end of MVP, we should have:

```plaintext
Input:
- local codebase path

Processing:
- scan files
- chunk source code
- embed chunks
- store in Qdrant/FAISS

Query:
- user asks natural-language question
- retrieve top-k chunks
- generate answer

Output:
- answer
- relevant files
- line ranges
- retrieved source chunks
```

This MVP is simple enough to build quickly, but it still gives us a clean foundation for the next stage: **function-level chunking, graph extraction, caller/callee, workflow extraction, and unused-code detection.**
